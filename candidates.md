# Candidates — Fortune Cookie Wisdom for Developers

Gate: one original fortune-cookie line for a software developer, single line,
1–120 characters, written to `/output/entry.txt`.

Judge: a tired senior engineer. Criteria, most important first:

1. One original line of fortune-cookie wisdom for a developer — not a slogan,
   punchline or generic advice.
2. Reads like a fortune cookie: one short balanced sentence that lands in a
   single breath.
3. Says something true about a developer's day: bugs, reviews, deploys,
   estimates, legacy code.
4. Turns that truth in a way the reader has not heard before, not a familiar
   saying.
5. Leaves a quiet twist or double meaning that rewards a second read.

## The slate (14 drafts)

1. The bug you cannot reproduce is not hiding from you; it is waiting for the demo. (80)
2. Your estimate was not wrong; it was a letter to a future where nothing else went wrong. (87)
3. The code you are afraid to touch is the code that pays for everything else. (75)
4. A green build is a promise the code made to the compiler, not to you. (69)
5. You will fix the bug in an hour; you will spend the week deciding whose bug it was. (83)
6. The comment says temporary; the calendar says four years; both are telling the truth. (85)
7. Your next deploy will go smoothly, which is how you will know nobody noticed it. (80)
8. The senior who wrote this code was you, eleven months and three deadlines ago. (78)
9. Every estimate is two numbers: the one you say, and the one you pray for. (73)
10. The test you skip today becomes the incident you explain tomorrow. (66)
11. A reviewer who finds nothing has not read your code; one who finds everything has not read theirs. (98)
12. The meeting about the bug will be scheduled faster than the fix, and both will be called urgent. (96)
13. Legacy code is just code whose author left before the questions arrived. (72)
14. The documentation is accurate, complete, and describes the system you replaced last spring. (91)

## Duels (criteria applied in order)

- #10 vs #4: #10 is advice wearing a fortune's coat — criterion 1 cuts it.
  #4's promise-to-the-compiler turn is quieter and truer. #4 advances.
- #9 vs #2: both are about estimates. #9 is a familiar two-numbers joke;
  #2 reframes the estimate as a letter to an unlived future — fresher on
  criterion 4. #2 advances.
- #1 vs #7: #1 leans on the well-worn demo-god trope. #7 finds the sadder
  truth — a smooth deploy is an invisible one. #7 advances.
- #5 vs #12: both are process truths, but #12 is a complaint, not wisdom;
  #5 at least balances fix against blame in one breath. #5 advances.
- #11 vs #6: #11 is long and prosecutorial. #6 is balanced like a slip
  should be, and "temporary" quietly changes meaning between the comment
  and the calendar. #6 advances.
- #14 vs #13: #14 is a good joke about stale docs, but it is a joke first.
  #13 defines legacy code by absence — the author gone before the
  questions — which reads as wisdom. #13 advances.
- #3 vs #8 (the two strongest): #3 says the feared code is the valuable
  code — a real turn. #8 says the mysterious senior whose code you curse
  is your own past self. On criterion 4, #8's turn is the one nobody has
  heard phrased this way; on criterion 5, "senior" carries a double
  meaning (the senior engineer, and your older self) that only lands on
  the second read. #8 advances.
- Semifinal #4 vs #2: #4 is crisp but thin — one idea. #2 holds a whole
  planning meeting inside one sentence. #2 advances.
- Semifinal #6 vs #13: both quiet, both true. #13's definition is elegant,
  but #6's two witnesses — comment and calendar — both "telling the
  truth" is the more fortune-like balance. #6 advances.
- Semifinal #7 vs #5: #7's twist (success = invisibility) is a single
  clean turn; #5 spends its second half on blame, which a tired senior
  has heard too often. #7 advances.
- Final four — #2, #6, #7, #8: #2 is lovely but slightly long in the
  breath. #7 is a punchline in wisdom's clothing — criterion 1 cuts it.
  #6 is the most balanced slip of the four, yet its truth (temporary code
  is permanent) is one developers already quote to each other, so
  criterion 4 cuts it. #8 survives every criterion in order: it is wisdom,
  not a slogan; one balanced sentence; true about legacy code and every
  review ever held; a turn not heard before; and "senior" rewards the
  second read — the culprit and the reader are the same person.

## WINNER

The senior who wrote this code was you, eleven months and three deadlines ago. (78 chars)

## RUNNER-UP

The code you are afraid to touch is the code that pays for everything else. (75 chars)
